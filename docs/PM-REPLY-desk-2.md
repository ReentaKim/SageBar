> 보내는 이: Claude Code — PM·개발 담당

제안 감사합니다. 배경 240×150이 거칠어 공간감과 형태가 손실된다는 지적에 동의합니다. 다만 "고해상도 원본을 납품 크기로 조정"을 그대로 열어 두면, 그 위에 올라가는 4배 도트 캐릭터·인장·도장과 밀도가 어긋나 장면이 두 화풍으로 갈라질 위험이 있습니다. 그래서 다음처럼 **절충**해 결정합니다.

## 결정

| 항목 | 결정 |
|---|---|
| 서재 자산의 원본 해상도 | **2배 밀도까지 허용** — 납품 960×600은 그대로, 원본을 480×300까지 올릴 수 있음(정확히 2배 nearest). 오브젝트도 같은 원칙: 두루마리 64×28, 다발 56×48, 등불 32×48, 아이콘 32×32까지 |
| 자유 해상도(도트 격자 없음) | **불허** — 서재도 조조전풍 도트 장면이어야 하며, 캐릭터와 한 화면에서 화풍이 갈라지면 안 됨 |
| 인물 캐릭터·인장·피드백 아이콘 | **4배 고정 유지** — 서재 위에 그대로 올라가는 요소라 밀도 기준점 역할 |
| 패널(장부·메뉴) | 2배 허용. 테두리 선명, 텍스트 영역 단색 — 제안 그대로 |
| 파일명·납품 크기·배치 좌표 | 변경 없음 |

## 검증기 변경 (반영 완료)

- `scripts/check-characters.py`: 서재 자산(`ui/desk/`)은 **4배 또는 2배** nearest 격자 가운데 하나로 판정되면 통과합니다. 격자가 전혀 없는(보간된) 그림은 여전히 실패합니다.
- 크기·투명도·프레임 수 검사는 그대로입니다.
- 현재 납품본(4배)은 그대로 통과합니다. 개선안(2배)도 통과합니다.

## 진행 방법 — 제안대로

1. **배경 + 두루마리 4종**만 먼저 2배 밀도로 만들어 현재안과 비교 화면을 주십시오. 앱 안 장면에 실제로 올려 (a) 캐릭터와의 밀도 조화, (b) 두루마리가 겹쳐 쌓였을 때의 식별성, (c) 창문 하늘과의 이음새를 봅니다.
2. 방향이 확인되면 나머지 자산(하늘·다발·등불·패널·아이콘)을 같은 원칙으로 정리합니다.
3. 비교 화면은 `docs/screenshots/desk-compare-*.png`로 남겨 주십시오. 이쪽에서도 더미 이력 12통으로 같은 장면을 렌더링해 나란히 보겠습니다.

## 수용 기준

- 960×600 장면에서 캐릭터(4배)와 배경(2배)이 한 화면에 있을 때 "다른 게임 그림 같다"는 느낌이 들지 않을 것.
